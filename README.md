# Sleeping Server Stopper
[![Modrinth](https://img.shields.io/badge/Modrinth-EmptyServerStopper-green?logo=modrinth&logoColor=white)](https://modrinth.com/project/nuRsj5Nz) Get on Modrinth!

A server-side mod that shuts a dedicated server down once it has been empty for a few minutes. It's a port of the [Sleeping Server Stopper Spigot plugin](https://github.com/vincss/mcEmptyServerStopper), meant to be used with [SleepingServerStarter](https://github.com/vincss/mcsleepingserverstarter) by [vincss](https://github.com/vincss).

Only the server needs the mod. It does nothing in singleplayer or on LAN worlds.

## Config
On first launch the mod writes `config/sleepingserverstoppermod.properties`:

```properties
# How many minutes the server must be empty before it shuts down. (Minimum is 1 minute!)
shutdownTimeInMinutes=2
# Should the shutdown countdown start as soon as the server launches?
shutdownOnLaunch=true
```

> **Upgrading from 3.x:** the old `sleepingserverstoppermod-common.toml` / `.cfg` files are no longer read. Copy your values into the new file.

## Building
Every jar is built from one codebase:

```
core/                  Plain Java 8 logic (countdown, config) shared by every build, with unit tests
src/                   Loader entrypoints for the modern builds, versioned with Stonecutter comments
versions/<mc>-<loader> Generated by Stonecutter, one Gradle project per Minecraft version + loader
legacy/<loader>-<mc>/  Standalone builds for loader versions that need different tooling
```

```sh
./gradlew :core:test                    # unit tests
./gradlew buildAll                      # every modern jar  -> build/libs/<mod version>/
./gradlew :1.21.1-neoforge:build        # one version
./gradlew -p legacy/forge-1.12.2 build  # a legacy version -> legacy/forge-1.12.2/build/libs/
```

Gradle downloads the JDKs it needs automatically, including Java 25 to run Gradle itself.

- Modern versions use [Stonecutter](https://stonecutter.kikugie.dev/) with Fabric Loom, ModDevGradle (NeoForge 1.20.6+) and ModDevGradle legacyforge (Forge 1.17.1 – 1.20.1). Version-specific code uses comments like `//? if <1.19 {`. Switch which version your IDE sees with the Stonecutter tasks in the `stonecutter` Gradle group.
- Each modern node is built against the lowest version of its range and claims the whole range (`mod.mc_compat`). This works because the game names the mod calls stay the same across the range: intermediary on Fabric before 26.1, SRG on Forge 1.18 – 1.20.1 (Forge renumbered them in 1.20.2), Mojang names on NeoForge and on Forge 1.20.6+. To support a newer version, widen `mod.mc_compat`, add it to `mod.smoke_versions` and run the smoke test. Add a new node only when a version breaks the existing jar.
- `legacy/forge-1.21.6` (Forge 1.21.6+, which uses the new EventBus 7), `legacy/forge-1.21.1` (Forge 1.20.6 – 1.21.5), `legacy/forge-1.20.4` (Forge 1.20.2 – 1.20.4), `legacy/neoforge-1.20.4` (NeoForge 1.20.2 – 1.20.4) and `legacy/forge-1.16.5` use Architectury Loom. `legacy/forge-1.12.2` and `legacy/forge-1.7.10` use [RetroFuturaGradle](https://github.com/GTNewHorizons/RetroFuturaGradle).
- The mod version is set once, in `stonecutter.properties.toml`.

## Testing
`./gradlew :core:test` covers the countdown logic. The smoke test covers everything else: for each jar it boots a real dedicated server on every Minecraft version the jar claims (both ends of its range and one version per minor release in between), has a bot join and leave, and checks from the server log that the mod cancels, restarts and finishes the countdown and that the server exits cleanly.

It needs [Node.js](https://nodejs.org/) 22+ and, for the default mode, [Docker](https://www.docker.com/products/docker-desktop/).

```sh
cd test/smoke && npm ci && cd ../..     # once, installs the bot

node test/smoke/run.mjs --build         # build every jar, then test all of them in Docker
node test/smoke/run.mjs --only 1.21.1   # one Minecraft version, loader or target (see --list)
node test/smoke/run.mjs --dev --only 1.21.1-fabric   # quick check through Gradle's runServer, no Docker
```

Versions the bot can't join yet are listed at the end, and the script starts a server for each so you can join by hand. GitHub Actions builds the jars on pushes to `dev` and `master` and on pull requests; the smoke test there only runs when the workflow is started by hand.

[docs/TESTING.md](docs/TESTING.md) has the details. [AGENTS.md](AGENTS.md) is a runbook for pointing an AI coding agent at the tests.
